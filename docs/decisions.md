- 2026-11-26 (security fix asked for by the platform): a borrowed session is rechecked on every request, whether its token comes in the cookie or an `Authorization` header. A no from `canMasquerade` or the new optional `recheck` deletes the borrowed session and reports `onStop` with `revoked: true`. The check is an auth strategy that always returns no user, placed first on the auth collection, and it skips the stop endpoint so `onStop` is reported once. It fails closed: if the check can't finish, the borrowed token is ignored for that request. The delete reads the sessions again in a transaction, so a sign-in made meanwhile is kept and `onStop` is reported once. Masq now refuses a collection that isn't an auth collection, and a `useSessions` other than `true` or left out: when the config is built, again in `onInit` against the built config (a later plugin or the host can change it), and on every request, where a borrowed token is ignored and start refuses. It also refuses a `readOnly` that isn't a boolean. Stop matches the borrowed claim by user and session id, and with the state cookie present it ends the session only when the claim names the same masquerader and target. Shipped as 0.1.2.
- 2026-11-26 (security fix, K810; design choices by the engineer, for the lead to confirm): stop removes the borrowed session through the same `revoke` as the recheck (`src/revoke.ts`): in a transaction, sessions read again right before the write, three tries, and an answer saying whether this call removed it. `onStop` is reported by the stop that removed the session, so overlapping stops report once. If `revoke` throws, stop fails closed: 500 with `ok: false`, all three cookies cleared, no restore, a redirect to login, no `onStop`, and an error log with both ids. The own token is restored only after the delete is confirmed, because handing it back while the borrowed session may be alive would report a return that didn't happen. The state cookie now carries the borrowed session's id (`sid`), since that is the only way to know which session a state names. Stop ends exactly that session, including when the browser lost its token or another token signs in beside the cookie, and `expired` is true only when that session was already gone or its hour was over. A state cookie without `sid` (issued by 0.1.2 or earlier, at most 24 hours old) keeps the 0.1.2 match by masquerader and target, ends nothing on a mismatch, and reports `expired` only once the hour is over. Known limit: a later, non-overlapping repeat of stop reports `onStop` again with `expired: true`; fixing that needs a stored record of ended masquerades.
